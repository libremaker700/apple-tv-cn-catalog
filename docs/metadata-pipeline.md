# 中文片名与简介补查流程

入口为 `scripts/title_lookup.py`，每天由现有 GitHub Actions 任务执行。App 下载经过校验的资料，电视端不保存搜索密钥。

1. 按苹果官方作品 ID、英文原名、电影／剧集类型和年份读取已核实缓存。片名和简介分别判断是否缺失；已有片名不会阻止继续补查简介。
2. 先查豆瓣的公开搜索与作品页。搜索结果只定位作品，必须读取作品定义、首播／上映年份及类型才能采用；简介取作品页的“剧情简介”段落。
3. 仍缺字段时查维基百科。读取定义、明确的中国大陆片名字段与“剧情”章节，保留对应网页链接。已核实片名可独立复用，继续查同一作品的简介。
4. 前两步仍未补齐时才调用 Tavily。每次只发一个 basic 查询，查找豆瓣、维基百科、百度百科等公开资料页。搜索摘要及搜索引擎生成的回答不直接写入片库；结果页仍需通过作品身份核验。
5. 简介去除网页标签、脚注和导航文字，要求为有效中文、35—600 字且至少含 20 个汉字；保存简介来源和检查时间。仅有英文资料时保留待补查状态；已人工核对整理的译文单独保存在 `data/summary-cache.json`。
6. 片名按核验结果校准并写入名称缓存，简介只补缺失字段，保存独立来源与重试时间。播放源 ID、集数、收藏与播放进度保持原有绑定。
7. 校验完整目录与所有图片哈希，先发布内容文件，最后发布版本文件。资料更新没有改图时，电视继续复用现有图片。

## 身份与年份

优先严格比较英文原名、类型、分季和年份。延期可能改变豆瓣首播年份；只有作品已有独立核实的 IMDb ID，且豆瓣页上的 IMDb ID 完全一致时，才允许名称／简介使用延期后的年份记录。此规则不会自动开启未上映作品的播放，也不会把旧季当成新季。

豆瓣别名中标有“港／台／香港／台湾”的区域译名不加入国内搜索别名。

## 缓存与失败处理

- 完整的核实结果直接复用。片名缺失通常 7 天后重试，简介缺失通常 1 天后重试；没有密钥时 1 天后重试。
- 403、418、重定向验证和网络故障会让对应主机暂停访问 6 小时；429 暂停 24 小时，不绕过验证、不切换密钥规避限流。
- 公共网页缓存仅持久保存访问状态、到期时间、链接和内容哈希；不公开保存整个网页或评论正文。
- Tavily 沿用共享月度预算，额度不足的作品保留排队状态。已找到的片名可以先发布，缺失简介继续等待，避免一次失败让整部作品丢失已核实资料。

执行日志 `logs/title-lookup.json` 包含实际阶段、公共请求状态、Tavily 查询次数及剩余缺失数量，可区分“未找到”“访问验证”“额度不足”和“已有结果复用”。
