# 已上线作品的云端查源

data/public-source-providers.json 与 App 的部署者预置逐项对齐，共 33 个片库，保留 App 稳定编号。29 个 CMS 地址不变；共享片库、爱看机器人、神话蓝光、B蓝光分别使用专用适配。

source-update.yml 自 2026-11-01 起每三天运行一次，默认取 12 部到期作品，手动单次最多 24 部。名称队列增加有上限、保存进度的自动别名发现，见 automatic-verification.md。每部作品向全部已登记片库查询经过核验的中文名和别名，保留带季数查询并有上限地补查基础名。尚未上线、没有核验中文名、当前季年份不明的作品不进行片源投票。

同片核验要求类型、季数及年份一致，并有有效豆瓣编号一致，或导演及至少两名主要演员相符。编号冲突、不同季和身份不明不能投票。同编号电影可容许相差一年的上映年份；片名年份后缀必须在身份核验通过后才能视作附加标注。一库多记录、多线路只投一库，别名票数由 GitHub 选择，App 不在详情页重新决定中文片名。

v5 将“已核验名称的查源召回”和“中文片名投票”分开。中文名/别名已通过审核后，可以按完整名称（忽略空格标点）、准确季数、年份及兼容类型召回媒体入口；不再强制要求片库提供导演和两名演员。纪录片剧集也可以参与。已知有效编号冲突、不同季、年份不符、解说/预告仍会拒绝。仅按名称召回的记录不能贡献改名票数、不能补造中文名依据；年份后缀也不能只靠相似名称删除。公开日志用 matchedRecords 与 identityRecords 区分召回和较强身份核验。已上线作品优先补中文名，失败和未确认作品继续轮转。

共享片库的类型以详情/搜索返回的 channelName 为准，并兼容频道 1/2/3/4 以及数字字符串。频道 4 实际返回“综艺纪录”，不能因旧代码只映射 1/2 而变成空类型；详情也会补齐类型。未知频道保持未确认，不猜成电视剧。

每部作品最多 90 秒、单源最多 20 秒、4 个源并发；每源最多 12 个去重查询及 4 次详情补充。网络失败、接口受限、配置缺失或身份待核验保留待重试状态，不能变成“未收录”。失败尝试轮转，避免长期失败的队首阻塞未检查作品。源范围变化使旧范围的否定结论失效。

共享片库依赖有效会话；神话蓝光/B蓝光依赖橘汁协议配置。工作流只从 Actions 加密 Secrets 读取，不把会话、协议密钥或播放地址写入源码、公开报告或目录包。未配置时分别输出 needs_configuration。爱看机器人遇到 403、验证或限流停止本次查询，不绕过限制。

`found` 表示按已核验名称及作品边界取得直接媒体入口；库名投票还要求更强的编号或演职员依据。两者都不能证明清单/分片当前可访问，更不能代替电视播放器实际出画面。公开日志保留片库编号、HTTP 状态和符号化原因；不保存请求头、完整响应、令牌或临时媒体 URL。

2026-11-01 的正式 Actions 批次（41285825078）覆盖范围为 313 部已上线且中文名已核验作品：复用 3 部近期状态，实际查询 12 部，8 部取得经过身份核验的直接媒体入口，4 部保留待核验/重试，另有 298 部尚未轮到。每部登记目标均为 33 个片库；没有出现 needs_configuration，说明两个私有 Secrets 已被工作流读取。部分片库仍有网络、身份或时限不足，不能称为 33 个源全部播放验证通过。

后续 v4 策略进一步把 HTTP 400/404/422 视作查询不完整：仍继续尝试基础名和其他别名，但这些 HTTP 错误不能证明片库没有收录。新策略会使旧否定结论失效，成功入口继续保留，等待后续有上限的复核。
